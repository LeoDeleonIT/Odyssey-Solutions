Exchange Online EWS Changes in October 2026

Published October 5, 20264-minute readPublished by Odyssey Solutions · Guidance for Greater Houston businesses.

If a business application connects to your Microsoft 365 email or calendars, ask its vendor whether it still uses Exchange Web Services, or EWS. Microsoft has scheduled a phased change to EWS access in Exchange Online during October 2026. An overlooked connection could interrupt a workflow even while employees can still open their inboxes.

The important detail is the rollout. Microsoft's September 4 Exchange Team update says the timing depends on when the change reaches the tenant. Business owners should have their administrator check the current Microsoft 365 Message Center notices and actual configuration instead of treating one public date as proof that every organization has already changed. Microsoft's rollout explanation

For a Houston office, the useful next step is a short, evidence-based review of connected applications. The following process helps turn a technical retirement notice into an owned business task.

Understand which connection is changing

EWS is an interface that software can use to work with Exchange information. This retirement concerns Exchange Online. Microsoft's original announcement expressly distinguished it from EWS in on-premises Exchange Server. Confirm the actual connection used by each application; an application installed on a local server may still connect to Exchange Online. Microsoft's scope announcement

Avoid assuming that every Microsoft 365-connected product is affected. Ask vendors for the interface used by your installed version and enabled features. A product name, a cloud logo, or a successful user sign-in is not enough to establish that answer.

Build a list that the business can recognize

Ask the Microsoft 365 administrator to review the EWS usage report. Microsoft documents its location under Reports, Usage, Exchange, and the EWS usage tab in the admin center. The report includes application IDs, operations, call volume, and last activity. It supports 7-, 30-, and 90-day views. Microsoft's EWS report guide

Next, translate those technical identifiers into a working list. For each entry, record the product, installed version, business purpose, internal owner, vendor support contact, and next scheduled use. Give priority to connections supporting customer communication, calendar coordination, record capture, or another time-sensitive task.

Include a status for unidentified applications. Someone should investigate each unknown entry rather than guessing that it is obsolete or approving it merely because it appears in a report.

Check jobs that run infrequently

The report is not a live outage monitor. Microsoft says its usage data is aggregated weekly and can take up to 10 days to appear. Combine it with vendor answers and the office's actual work schedule.

Ask about month-end reports, occasional imports, quarterly processes, and integrations that are used only by one department. Have staff describe the task and the application they open. This conversation can reveal a dependency that a short reporting window does not explain.

For example, if a finance workflow runs only after month-end, include its next run in the test plan. Do not close the review solely because email worked on Monday morning.

Have an administrator review temporary access controls

Microsoft's EWSAllowedAppIDs feature identifies permitted applications by their application IDs. During retirement enforcement, an organization that still requires EWS needs the appropriate tenant setting and application allow list. The older, similarly named EWSAllowList uses user-agent information and is a different control. Microsoft's application allow-list guidance

Have the administrator compare the current settings with the verified application inventory and the latest tenant notice. Changes should be reviewed, documented, and tested with the affected vendor. Avoid copying an unfamiliar application ID from a discussion forum or enabling access without knowing what business task it serves.

Any temporary accommodation should have a named owner and a migration date. Continued operation today does not establish that the application is ready for retirement.

Get a specific answer from each vendor

Ask for the supported replacement version or connection method, its availability, any licensing dependency, and the steps required in your environment. Microsoft recommends identifying EWS applications and working with vendors on migration; its roadmap also warns that capability targets can change. Microsoft's retirement roadmap

A useful vendor response should let you plan the work. Request written answers to these questions:

  • Does our current configuration use EWS in Exchange Online?
  • Which functions depend on it, and what will replace them?
  • What must our administrator approve or configure?
  • What test demonstrates that the replacement works?
  • Who handles a failed test, and what is the supported recovery plan?

Keep unresolved answers visible to the business owner. A promised future release needs another decision date.

Close the task after a workflow test

Choose an approved test record or nonconfidential sample. Have the normal user perform the complete task, then verify the expected result in the receiving system. Check scheduled operations as well as interactive features, and record the version, date, tester, result, and remaining exceptions.
